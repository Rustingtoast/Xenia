## Project

- Xenia is a phone book web app. It must work well in **both desktop and phone browsers**;
  the UI is **mobile-first** (issue #10).
- Repo: https://github.com/Rustingtoast/Xenia. The roadmap lives in the GitHub issues:
  - #1 Rails as backend (branch `1-beta-test-ruby-on-rails-as-backend`, PR #14)
  - #2/#3 SQLite + backend structure
  - #4 phonebook list page: fields are **Group, Location, Phone number**
  - #5 create entry, #6 edit entry
  - #7/#9 search/filter by group, location, phone number (combinable), highlight matches
  - #8 login, encrypted; users register and **each user has their own phonebook**
  - #11 export to Excel
  - #12 emergency wipe: user sets a PIN at registration; entering it + confirming deletes all their contacts
  - #13 scheduled backups to a chosen location (e.g. USB), importable; backups also wiped on emergency removal

## Stack decisions (and why)

- **Full-stack Rails 8.1, not `--api`**: the app serves the website itself. (It was first generated as
  API-only by mistake and regenerated.)
- **Tailwind CSS v4** for mobile-first styling (unprefixed = phone, `md:`/`lg:` = larger).
- Hotwire (Turbo + Stimulus) via importmap; SQLite; Solid Cache/Queue/Cable.
- **Ruby via mise, not rbenv**: the user chose mise. On this machine mise is first in PATH and rbenv is
  installed but shadowed. Ruby 4.0.9 is pinned in three places that must stay in sync:
  `mise.toml`, `.ruby-version` (CI), `ARG RUBY_VERSION` in `Dockerfile`.

## Working here

- In non-interactive shells, run Ruby through mise: `mise exec -- bin/rails ...` or `mise run <task>`.
- Tasks: `setup`, `dev`, `dev:lan` (phone testing on the LAN), `test`, `test:system`, `lint`.
- Run tests with `mise run test` (same command as CI: `bin/rails db:test:prepare test`), not bare
  `bin/rails test`: the bare command hid the CI failure once.
- `bin/dev` started in the background dies right away: the Tailwind watcher exits when stdin is closed.
  Keep stdin open (`tail -f /dev/null | mise run dev`) or use `tailwindcss:watch[always]`.
- Mac's LAN IP for phone testing was 192.168.2.63 (`ipconfig getifaddr en0`).

## CI (`.github/workflows/ci.yml`, generated by `rails new`)

- Runs on PRs and pushes to `main`: brakeman, bundler-audit, importmap audit, rubocop, test, system-test.
- `db:test:prepare` needs **`db/schema.rb` committed** (an empty schema until the first migration).
- The `system-test` job needs the **`test/system/` directory** to exist (Rails 8.1 doesn't create it).
- `gh` is not authenticated, so Actions logs can't be fetched via the API (403). To debug, either ask for
  `gh auth login` or reproduce: copy `git ls-files --cached --others --exclude-standard` into a scratch dir
  and run the workflow's commands there.
